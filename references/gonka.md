# JoinGonka transport and generation limits

Primary sources: [API reference](https://gate.joingonka.ai/docs/api.md), [errors and limits](https://gate.joingonka.ai/docs/errors.md), [model cards](https://gate.joingonka.ai/docs/models.md). Check `/v1/models` and `/v1/capabilities` for current values.

Output ceilings reported on 2026-10-12: GLM 5.3 Flash and MiniMax M2.7: 8192; DeepSeek V4 Flash: 32768. Context windows are separate: 390000, 200000, and 380000 respectively. The output budget includes reasoning; a small cap may finish without any final answer. Streaming without an explicit cap uses the model ceiling; non-streaming defaults are lower.

The gateway passes `reasoning_effort` through and supports lowering reasoning. Use `low` for short worker and judge briefs; do not use undocumented fields to disable reasoning.

The client bounds each request to 180 seconds by default (adaptive per model from the health cache: at least 60 s, at most 360 s unless `--timeout` is explicit). By default a retryable primary failure launches the remaining fresh same-model workers with the original prompt and snapshots, at most five attempts total (cap six); replicas do not multiply. Because the gateway streams, the client hedges on time-to-first-token: no streamed `data:` event (keepalive comments do not count) within the adaptive delay starts two extra replicas. Whole-attempt timed hedging stays opt-in with `--hedge-after SECONDS`. Councils probe every model with a 1-token request first (15 s), skip models in cooldown, substitute failed models, start the judge at quorum and fall back through a judge chain. HTTP 401/403 means the key was rejected (note `/v1/models` answers without valid auth, so discovery alone does not prove the key works); the client stops immediately instead of substituting. Multi-turn attempts and the later judge have their own bounded requests, so 180 seconds is not a council-wide deadline. The first successful result for a model wins, and the local client stops waiting on its sibling replicas. The gateway cannot cancel requests already accepted, so they may continue processing and incur estimated input usage. Backups and optional timed hedges may increase billed usage; providers may still be slower than the request limit. Streams send keepalive comments every 15 seconds, usage near completion, and a terminal reason. `joingonka-stream-stalled` is an incomplete response even if it says stop; `joingonka-stream-unfinished` reports length. Stream errors can arrive after HTTP 200. Never treat a bare disconnect as successful completion.

When length is reported, send received partial output with full history in the next request and continue. This spends input tokens again and is a new request. Truncated tool arguments must not be executed. Stop after the configured continuation limit. Responses API is stateless on this gateway; do not use previous_response_id or server-side compaction.
